## 量測環境與方法

Headless Chromium 156.0.8078.79，Debian 13／Linux 6.18.57，Intel Xeon Platinum 8370C，容器可見 5 個邏輯 CPU，CPU 配額 4 核、記憶體上限 16 GiB。Canvas 與 WebGL 分別量測，WebGL 由 CDP 確認為 ANGLE Vulkan／SwiftShader 5.0.0 軟體轉譯。桌面視窗 1280×800，模擬手機 852×393、平板 1180×820，DPR 1。模擬行動端採 Chromium 的 mobile viewport／touch 設定，尚未測 iPhone Safari、iPad Safari、iPhone 主畫面 PWA 與 iPad 主畫面 PWA。

正式 build 使用本機 Vite preview 的 GitHub Pages 子路徑，未節流 HTTP loopback。每個條件採三個獨立 browser context，各一冷一暖；冷是新 context HTTP 快取，暖是在同一 context reload，可從 transferSize 交叉核對。保留伺服器與 OS 快取自然狀態，封鎖 Service Worker。試驗有其他 QA 瀏覽器工作並行，WebGL 數據尤其受軟體渲染與資源競爭影響。

- **首次繪製**是 navigation time origin 至既有 Phaser POST_RENDER 診斷變更的 DOM observer 時間。此數值與頁面最早載入提示、合成輸出及物理顯示時間各自獨立。
- **可操作上界**是自 navigation 到 Playwright 觀察到既有首繪、載入解除、地標成功。首次按鍵與渲染反應另測。上界含自動化輪詢延後，與從 iOS 開啟圖示到可見操作的計時分開。
- **幀時間**用前景 requestAnimationFrame 間隔，保存 0.1 ms 分箱、逐次 >250 ms 停頓、樣本數及 P95（nearest rank）。測試循環在入口附近四向鍵盤交替，含停步。它描述瀏覽器送幀節奏，不涵蓋整條候選路線或實機觸控。短測為每條件最後一組暖載的單趟樣本。
- **輸入反應**是 Vite dev 測試 tab 中，瀏覽器 keydown 至首個顯示該方向 Run 紋理的 Phaser POST_RENDER。每版每 renderer 20 筆（每方向 5 筆）；實體觸控、劍或閃避及螢幕呈現延遲仍待測。
- **記憶體**區分 Chromium `performance.memory.usedJSHeapSize`、CDP `Runtime.getHeapUsage` 和註冊紋理的 width × height × 4。後兩者於固定回訪取樣，未觸發 GC。所有資料皆缺 iOS 程序記憶體、GPU 運用與實際解碼峰值。

**15 分鐘試跑。** PR #39 Canvas 手機模擬前景連續 901.944 秒、302 次四向短移動循環、43,361 個 rAF 間隔。未記錄頁面錯誤或失焦，結束時畫布及啟動狀態正常。P95 為 50.0 ms，一筆 283.3 ms 停頓，時間點為 navigation 後約 779.86 秒。試跑和部分其他 QA 瀏覽器工作重疊，停頓成因尚未定位。暖載 JS heap 指標在記錄開始約 27.51 MB、結束約 16.88 MB，採樣時機和 GC 不固定，不能用於判斷洩漏。此試跑主要驗證持續運轉，完整路線及換區壓力留待真機和候選。[15 分鐘原始觀察](stable-canvas-phone.json)

## 固定畫面、輸入、三次回訪

同 renderer 七個鏡位比較 PR #39 與 PR #42。Canvas 七鏡位均為零像素差，PR #39 神龕後待機 30 秒仍有 3,535 個角色像素超過亮度門檻，PR #42 為 3,585。兩版的互動寶箱及東側回南口均完成。四向鍵盤反應的 Canvas P95 分別為 7.3 ms、4.5 ms。20 筆逐次樣本保留。這是遊戲事件至描繪代理，與肉眼、雙指動作和 G04 戰鬥反應分開。[Canvas 畫面與反應](visual-canvas.json)

Canvas 三次靜置 30 秒回訪，每版各三筆。兩版預設解析度 都有 44 個列出的紋理來源，每趟合計 54,345,520 bytes（約 51.83 MiB RGBA），與歷史約 52.09 MiB 的估算方法分別紀錄。兩版 JavaScript heap 使用量第三趟相對第一趟約 100.6% 與 96.2%；個別值受 GC、開發伺服器、操控與工具影響。回訪以固定測試鏡位加上實際捷徑互動在同一場景重複取樣。整合候選需用真正換區、動態新增貼圖、原生裝置與相同操作腳本重測。[三次記憶體及逐紋理觀察](visual-canvas.json)

WebGL 七個固定鏡位也都是零像素差，兩版神龕後的固定幀各有 3,498 個可辨角色像素。四向鍵盤代理 P95 分別 42.5 ms 與 12.0 ms，受軟體 renderer 及並行工作影響。WebGL 三次回訪各靜置約 1 秒，註冊估算與 Canvas 相同。既有畫面腳本也在 PR #42 的 Canvas 和 WebGL 各通過六次角色可見測例，正式入口與 Batch C 五個固定鏡位逐像素相同。這些比對維護現有畫面基準，製作人仍須另行簽核候選藝術品質與手感。[WebGL 畫面與反應](visual-webgl.json)

## 放行門檻建議

| 原提案 | 目前建議 |
| --- | --- |
| 冷可操作 ≤12 s、暖 ≤5 s | 先保留為保守的試測目標。Loopback 明顯低於此值，仍需以兩款實機、各兩種模式、同一 HTTPS 網路的穩定版與候選成對量測，再由製作人確認。報告保留個別值及最差值。 |
| 首次繪製 ≤1 s | 不適合直接設定為首幀發布門檻。有效穩定樣本已超過 1 s，先把 1 s 用於可見載入回饋的試測，獨立追蹤遊戲首幀與可操作差距。載入回饋本次未直接計時。 |
| 輸入 P95 ≤150 ms | 保留真機觸控試測目標。本次鍵盤代理尚未含 iOS 觸控、揮劍、閃避或顯示延遲。真機各取至少 20 筆可行動狀態的揮劍與閃避樣本。 |
| 幀 P95 ≤33.3 ms | 保留原生裝置前景的試測目標。Canvas 短測約 16.8 ms、長跑 50.0 ms，雲端軟體 WebGL 短測 83.3 ms，依 renderer 與同機穩定版配對分析。 |
| >250 ms 停頓 | 長跑已觀察到 283.3 ms，當作需定位的前景事件，報告每筆時間與場景；載入、旋轉、背景及觀測器暫停單列。真機確認是可重現的可玩性阻斷再設定放行門檻。 |
| 重訪第三次 ≤第一次 110% | 暫不作硬閘；三筆 CDP／解碼估算的代理不足以代表整體記憶體。先盯相同資產配置的紋理駐留、回訪是否單調增加及是否出現重載，再在真機核准具一致取樣條件的指標。素材新增 P0 約 5.39 MiB，P1 同時新增駐留頁擬 ≤8 MiB，皆為待驗預算。 |

正式候選需重跑相同入口、實機共四格、成對冷暖啟動及實際路線的 15 分鐘穩定性。啟動黑屏、非預期重載、資料或退路損壞仍依原展示計畫阻擋。通過 SHA、恢復方式以及製作人對客觀與主觀證據的審閱仍待整合。
