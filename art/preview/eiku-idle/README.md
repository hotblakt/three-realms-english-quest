# 影空待機候選圖驗收

**判定：可預覽，正式圖集驗收不通過。**

- **原檔 PASS**。位元逐一保留於 [eiku-idle-candidate.png](../../reference/eiku-idle-candidate.png)。SHA-256 為 `e27a90a5e44c2b09c039dfd68833083df6a5ee05b2d18f9319dcc3f5d6bac069`。
- **方向與分格 PASS**。1774 × 887，八欄、四列，由上往下是南（正面）、北（背面）、西（朝左）、東（朝右）。按原尺寸的等分邊界取整，格寬、高各為 221 或 222 px。32 格主體可分開，肉眼未見角色交疊到相鄰格。表格邊界只用於預覽。
- **外型一致性 PASS，腳底定位 FAIL**。髮型、護額、配色與剪影整體一致，圍巾有可見變化。用亮度低於 165 的深色像素估算，角色高約 194–201 px；同列腳底的垂直差約 0–1 px。以底部 12 px 深色像素外框的水平中點估算，南、北、西、東分別約漂移 2.5、4.5、6.5、8.5 px（原圖尺寸）。側面循環有水平滑動，需重新對齊。這些數字為輪廓代理值，無法取代實際腳底接地點逐格校正。
- **透明度 FAIL**。8-bit RGB PNG，沒有 alpha 通道或透明色資訊。空白處可取樣到 RGB `(244,244,244)` 與 `(254,254,254)` 等淺灰像素，棋盤格已烘進圖像。直接裁切或縮小都會留下背景；用亮度一鍵去背也可能誤去護額、髮絲高光與半透明邊緣。
- **正式 96 × 96 貼圖 FAIL**。對照[正式圖集規格](../../production/eiku/README.md)，角色目前約 194–201 px 高，不能直接裁成 96 × 96。若有乾淨透明原稿，可等比例縮至 62–66 px 站姿高度，再逐格排入統一格；不應把整格硬縮至 96 × 96。

## 需重出或校正

1. 從有透明角色圖層的原稿重出 32 個 RGBA 待機影格。如果只有這張合成圖，要逐格重建 alpha 並修清髮尖、圍巾、刀與鞋邊，避免灰邊；必要時從透明底重新生成。
2. 四向統一角色比例與鏡頭，固定每格 96 × 96，站姿高 62–66 px，腳底定位到 `(48, 72)`。校正側面水平飄移，尤其東向從第八格接回第一格的落差，並檢查頭身、佩刀、腳步和飄帶各列循環。
3. 出圖保留透明留白及至少 2 px 格間距，再用正式命名打包。這次只評估待機，步行、揮劍和閃避仍需另交 96 格，方可交付完整正式 `eiku.png` 與 `eiku.json`。

## 本機檢視

在儲存庫執行 `npm run dev`，開啟 Vite 網址下的 `/art/preview/eiku-idle/`。預覽圖集描述檔共用原始 PNG，避免複製圖檔；每格以原像素比例裁切，可暫停、單步與開啟格中央和參考腳底線。正式建置中的[影空美術工作台](https://hotblakt.github.io/three-realms-english-quest/art-workbench/)也提供這組四向待機參考。
