# 影空 2.0 右向跑步

從美術工作台進入「霧竹林角色構圖」，向右移動即可看跑步。右上「構圖設定」可選固定站姿、隨移動播放或原地試播。按「暫停動畫」會停在當前格，再用「檢閱格」選第 1 至 6 格。畫面顯示選定圖集的實際檔案大小及播放設定 FPS。預覽只在霧竹林生效。[GitHub Pages 預覽（合併部署後更新）](https://hotblakt.github.io/three-realms-english-quest/forest-preview/)

## 來源、檢閱與相容匯入

私人庫固定提交 `151341b4ce8200bdd2449e6e547e1aa47436809c` 的原始 ZIP 保留原樣。ZIP CRC 檢查通過。兩張 PNG 均為 4608×3456 RGBA，每頁 6 欄 3 列，格尺寸 768×1152。依 `layout.json` 的頁起始索引與列優先順序解碼全部 36 格，每格都有透明與完全不透明像素。`timing.json` 的採樣時間單調遞增，36 個間隔合計 4458.333 ms，來源平均 8.075 FPS，穩定跑步段每格 125 ms。[來源雜湊、逐格 alpha 邊界與時間](eiku-run-provenance.json)

新版 FrameSprite ZIP 的隨機資料夾名可以變動。先檢查路徑、同名衝突、頁尺寸及 CRC，再讀 `layout.json` 和 `timing.json`，依頁的 `startIndex` 裁 2D 格位。Phaser 使用重打包的圖集和獨立動作清單，原始 4608 px 頁圖只在離線匯入時解碼，避免裝置紋理上限。用 `python scripts/import-framesprite-run.py /path/to/source.zip` 在已裝 Pillow 的工作目錄重現本次匯入。新角色或動作先檢閱所有格與時間，再設定循環段、共同腳底與縮放、輸出路徑和動作清單。可重用 `read_frames` 的分頁流程及 Phaser `AnimationClip`，本次腳底和 36 格約束需依新來源重審。

## 循環與構圖

逐格比對後選用來源索引 19–24（第 20–25 格）。19–21 和 22–24 分別由跨步到落腳、收腳，24 接回 19 是下一次跨步，排除前段站姿／加速與尾段收步。使用同一縮放及固定原點保留起伏；著地位置依共同地面線，騰空格保留空隙。弱 alpha 浮點與偏綠色邊緣保守處理，所選格無須切掉大片陰影。跑步按實際位移推進，碰到溪岸即回站姿。初跑從落腳開始，東向以外沿用既有站姿。跑步和站姿的藍圍巾、刀鞘與衣角仍有些許接縫跳動，奔跑姿勢與既有站姿的透視不同。

先前實機截圖的設定值未隨專案保存。此版本假設最大角色選項為 180%，提高 15% 得到 207%；以既有 1.3 倍攝影機作暫定值並保留選單。沉浸滿版的 400 邏輯像素高視窗中，跑姿約佔 27–29%，站姿約 30%；原始視窗留白時比例可不同。

- 256 px 圖集 768×512，175,824 bytes（171.7 KiB），RGBA 約 1.50 MiB。
- 384 px 圖集 1152×768，334,342 bytes（326.5 KiB），RGBA 約 3.38 MiB。
- 建議用 256 px 進行一般遊玩。兩版共用顯示高度與腳底，384 px 可在放大檢閱時保留較多圍巾、衣紋細節。兩版目前同時預載，合計約 4.88 MiB 解碼紋理，另計瀏覽器和 GPU 副本。Safari 實機的首次解碼及穩定幀率待驗。
