來源 `1e618f2d99d27ffde73e0aea57fb46d11fc3258f`（PR #33）。裝置核准基準 `d59072175a3856223805cc21fb2c48a8f99468b5`（PR #31）。依製作人回報，ChatGPT 內嵌瀏覽器和獨立 iPhone Safari 均停在四向動作載入。20 秒後顯示通用提示與重試按鈕。這只證明 HTML 看門狗有執行。

## 恢復範圍與證據

正常 `/forest-preview/` 的入口 HTML、啟動模組和植被實作取自 PR #31。場景的 Phaser 預載、同步初始化、四向必要圖集門檻及 Cast 背景載入均回到 PR #31。與基準的場景差異是把現有植被建立和透明度公式抽成可覆寫方法，預設仍執行原本的渲染與公式。第一章、溪流、碰撞、存檔與工作台設定未變更。Batch B 資產、來源、文件、測試和整個提交歷史均保留。正常入口不讀取診斷模式或 Batch B 圖集。

在同一 Chromium 環境下獨立建置 PR #31 與本分支。模擬 iPhone 852 × 393、iPad 1180 × 820，兩組均進場，HUD 一致，每組發出的 33 個 PNG／WebP 路徑完全相同。正常入口沒有 Batch B 或診斷資源請求。Vite 多入口建置的 JavaScript 分塊與雜湊會變動，此比較針對執行路徑和資產請求。

## 診斷操作

本機 `npm run build` 後執行 `npm run preview`，開啟 `/three-realms-english-quest/forest-diagnostics/`。在可存取該建置的裝置上，逐次執行 A、B、C、D、E，記錄第一個失敗模式與最後階段。每次提交表單都重新進入頁面，不清除快取或遊戲資料。先用自動渲染測冷啟動與重訪，再用 Canvas／WebGL 重跑失敗組。橫向畫面左上可選取並複製日誌，收起面板後可操作森林。

| 模式 | 使用相同 PR #31 啟動程式，逐項加上 |
| --- | --- |
| A | 基準場景，無竹林圖集。 |
| B | 取得同一份 228,190 bytes WebP，核對大小與 SHA-256，保留 Blob。 |
| C | 加上 Image 載入、尺寸檢查與瀏覽器支援時的 `Image.decode()`。保留解碼結果。 |
| D | 加上 Phaser 紋理註冊及預期幀檢查，仍繪製原地景。 |
| E | 加上 Batch B 竹叢、地面貼花和淡化。採用分段探針的載入方式，以隔離繪製變因。 |

日誌涵蓋入口、模組、渲染器、資產接收和處理、紋理註冊、四向必要幀、場景建立與首次繪製。逾時時顯示尚未收到的資產及已收到但尚無完成事件的資產。WebGL context 遺失也會顯示。日誌只存在當前頁面，無遙測、個資收集或自動上傳。此分支未部署。

## 回歸

`npm ci`、正式建置、47 項 Node 與 7 項 Python 測試通過。Chromium 行動模擬僅驗證回歸與診斷隔離。環境未提供可執行的 WebKit，前輪 Playwright WebKit 下載端點回傳 403。仍需 iPhone Safari 和 ChatGPT 內嵌瀏覽器先驗證恢復版正常入口，再比較診斷模式。

正式建置以 GitHub Pages 子路徑跑完 A–E、自動渲染及 A 組強制 Canvas／WebGL。故障注入可直接看到錯版本圖集內容、北向必要圖集 404 及缺少幀的就緒失敗。一般入口 Chromium 亦通過四向 Run／Idle、北向轉場足點、過橋與溪岸碰撞、寶箱、神龕、捷徑和兩種行動橫向觸控。
