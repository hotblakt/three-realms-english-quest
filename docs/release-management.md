# Work 發布協定

正式發布目標為 `hotblakt/three-realms-english-quest` 的 `main`。由製作人授權可合併的儲存庫、來源分支、提交及變更範圍。執行前後保留 PR、SHA、檢查、部署連結和時間。

1. **核對授權。** 驗證登入身分、儲存庫與目標分支。遇到權限缺失、範圍不明或無合併授權時，回報阻礙及目前進度。
2. **核對來源。** 以遠端分支指向的完整 SHA 和 PR 差異比對授權內容。確認無意外檔案，並記下基準分支。
3. **建立或重用 PR。** 找同來源及目標的既有 PR。若建立被拒，留下手動建立連結。PR 新增提交後重新確認授權及 CI。
4. **檢查合併條件。** 確認 PR 已準備審查、`PR quality gate` 對目前候選成功、沒有衝突，必要審閱及對話均已處理。遇到檢查失敗、尚未完成、內容漂移或核准撤回時暫停。
5. **依授權合併。** 最後再核對 PR head SHA，依設定的合併方式執行。保存合併 SHA。維持分支保護與權限原設定。
6. **核對部署。** 以合併 SHA 對應 GitHub Pages 工作流程與部署環境，等待結果。確認正式 URL 指向該版本並能載入入口與資源。部署失敗時記錄日誌與阻礙，另行確認修復或回復授權。
7. **瀏覽器煙霧測試。** 開啟正式首頁、進入第一章、試操作移動和戰鬥、檢查既有存檔及學習入口、核對 PWA manifest 和基本資源路徑，並從美術工作台進入霧竹林。涉及麥克風或觸控時，記錄實機、模擬或未測。現有 CI 未包含這些實際瀏覽器步驟。
8. **回報。** 列出合併與部署 SHA、PR 與工作流程網址、各檢查結果、煙霧測試平台、耗時、人工介入時間及尚未驗證項。

## 建議的分支保護

由有權管理設定的人員在首個 PR 檢查出現後與製作人確認啟用。保護 `main`，要求 PR、至少一位審閱者、處理必要對話，並在新提交時重新審查。禁止強推與刪除，針對推送與繞過保護採最小授權。必須在 PR 上通過由 GitHub Actions 發出的 **PR quality gate** 工作檢查，設定畫面若帶工作流程前綴，選取 **PR Quality / PR quality gate** 對應項。先核對實際顯示名稱，避免設定成部署工作或只要求其中一個測試分支。需要檢查合併後的內容時，要求分支更新到 `main` 或使用合併佇列。合併佇列可觸發同一門檻。本文件只提出設定建議。
