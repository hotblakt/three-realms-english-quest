# 影空 2.0 東向動作驗收

霧竹林「FrameSprite 自動方向」維持 207% 與 1.3 倍鏡頭。向右跑後停下會播放東向待機，向南會沿用南向跑步。面向東、放開方向鍵或搖桿，再按 K 或「施法」可看到手勢與風光。施法僅是預覽演出，沒有命中、傷害或技能解鎖。揮劍與閃避繼續使用既有玩法及回饋。

## 來源和逐套驗收

唯讀核對私有分支 `assets/eiku-east-actions-batch-001` 所固定的 `8fe3635aa793c1a46b903cc5df64985105079e41`。四份 ZIP SHA-256 均與需求一致。ZIP CRC 通過，合計 240 張 PNG 都能解碼，編號各由 000 至 059，帶透明與實色 alpha。每份含原始 README 和 timing.json，時長均為 4,458.333 ms，平均 13.458 FPS。待機、衝刺、施法為 768×1152，攻擊為 766×1150。60 格中，各套以 alpha >150 量測的邊界觸碰數均為 0。觸邊指標無法代替動作判讀。

| 動作 | 素材判定與範圍（索引從 0 起算） | 播放 |
|---|---|---|
| 東向跑步 | 沿用已核准的來源 19–24。兩次跨步交替，角色與碰撞比例不變。 | 6 格、8 FPS，循環 |
| 待機 | 採 0–30 的偶數格。雙腳固定，頭肩起伏細微，圍巾先擺開再收回，接縫仍略可辨。腰間配件和刀柄穩定。 | 16 格、7 FPS，循環 |
| 揮劍 | 10–13 蓄勢，14–32 向前伸手／保持，33–37 收勢。主動作像空手出拳，畫不出可信刀刃與打擊點。原稿前後有比例差，且在出拳段反覆維持同姿。拒用。 | 沿用即時劍光和既有命中流程 |
| 衝刺 | 8–17 前傾加速，18–48 反覆交替跨步，49–55 回正。是長跑段，原始腳底基準也比待機低。壓入現有 160 ms 閃避會丟掉加速或收勢。拒用。 | 沿用 160 ms 閃避與既有碰撞 |
| 施法 | 採 6–32 的偶數格。手抬起、短暫維持、向前伸展後收勢。畫面沒有可靠的能量球，於約 800 ms 的伸手格補上不帶傷害的程式風光。藍圍巾與刀鞘辨識度良好，手指與圍巾仍略有游移。 | 14 格、10 FPS，單次 1.4 秒 |

待機、施法使用共用比例與腳底原點。將弱 alpha 噪點、偏綠邊緣及腳後淡地影保守移除。這批可作霧竹林預覽。揮劍和衝刺需重新提供能讀出刀鋒接觸、短爆發與回復動作的素材，才有完整東向專用美術。

## 原稿與製作流程

「東向動作品質與原稿」按動作查看縮小的原始聯絡表及適用的處理後圖集。待機和施法也可從動作來源選擇原地播放、調速、停格及切換解析度。勾選「顯示腳底原點」可在實際縮放下對位。[待機](../art/preview/east-actions/idle.webp) · [揮劍](../art/preview/east-actions/attack.webp) · [衝刺](../art/preview/east-actions/dash.webp) · [施法](../art/preview/east-actions/cast.webp)

執行 `python -B scripts/import-framesprite-actions.py 來源ZIP scripts/recipes/eiku-east-idle.json 輸出目錄`。支援既有分頁及 PNG 序列。調整配方 `range`、`indices`、`fps`、`oneShot` 和統一腳底座標。匯入器先驗證檔案與順序，再輸出聯絡表、來源雜湊和核准動作的 lossless WebP。離線工具需 Pillow、NumPy，瀏覽器依賴維持原樣。

## 效能

| 圖集 | 256 px（1024×1024，RGBA 4 MiB） | 384 px（1536×1536，RGBA 9 MiB） |
|---|---:|---:|
| 待機 | 407,646 B | 789,640 B |
| 施法 | 380,908 B | 738,032 B |

首屏只請求既有 256 px 東向跑步圖集（175,824 B，約 1.5 MiB RGBA），其他按所選來源、方向或施法動作載入。行走與碰撞可在請求中繼續，並使用站姿。每次顯示一張圖集。已拜訪的圖集留在預覽頁的 Phaser 快取內，切過兩種解析度會累加。在只體驗東向三個核准動作且固定 256 px 的情況下，新增待機和施法各 4 MiB，三張合計 9.5 MiB 紋理，另計 GPU 副本與場景。Safari 的真實網路下載、首次解碼及長時間記憶體待驗。

## 實機驗收

1. 在 iPad／iPhone 橫向 Safari 與獨立 PWA 確認搖桿、揮劍、閃避、施法與構圖視窗可觸控。
2. 向東跑、停下待機、再按施法，確認腳底與鏡頭維持穩定。向南跑應保留九格循環。
3. 施法期間按揮劍或閃避，確認施法中斷且原操作可用。首次施法與切換 384 px 時注意是否掉幀。
4. 反覆切動作及解析度並檢查 Safari 記憶體。重新進入第一章確認語音、戰鬥與存檔。
