# 霧竹林 Batch B｜實機驗證後的整合候選版

基準為 PR #34 合入的 `08988dacecacbd01dfbda2323667c1f301280f5e`。製作人已在 Safari 實機驗證正常入口與 Auto 模式 A–E 全部通過。這份結果證明 Batch B 圖集和完整生態能在該次裝置及載入路徑下運行。原本 PR #32／#33 卡死的實機根因仍未確定。

## 啟動順序比較

| 階段 | PR #32 正常入口 | PR #33 正常入口 | PR #34 診斷 E、已通過實機 |

PR #32 已在模擬環境中重現「選用圖集缺少完成／失敗回呼」造成的等待。PR #33 排除這項依賴後仍在實機失敗。PR #34 的結果不足以單獨歸因於動態模組、Blob 解碼、資源排序、GPU 初始化、HTTP 快取或資產時序。這些都是待進一步隔離的假設。

## 候選版啟動

`/forest-batch-b-preview/` 是獨立的 Vite 頁面。先由 HTML 顯示入口狀態，再動態初始化 Phaser。選用圖集及其模組獨立於必要預載，採用 E 驗證過的下載、雜湊、Image 解碼、手動紋理註冊與首次繪製順序。必要 Run／Idle 先驗證幀，仍由基準場景的原始門檻驗證一次。選用管線從預載開始最多五秒，失敗時回到原竹林；部分註冊的紋理會移除。圖集可用時沿用同一批次 B 的竹叢、地面貼花與遮擋。圖集維持 228,190 bytes 和 1.125 MiB RGBA。

頁面看門狗保留 20 秒。等待期間顯示資產識別碼、載入階段及耗時；完成以首個場景繪製為準。必要資產遺失或停滯時保持控制鎖定並顯示重試，重試只重新導覽原候選頁並附上查詢參數，無存檔操作。所有日誌只存在當前頁面。正常入口與 A–E 仍各自可用。指定 `?renderer=canvas` 或 `?renderer=webgl` 可切換渲染器；預設仍為 Auto。

執行 `npm run build`、`npm run preview` 後，本機候選路徑為 `/three-realms-english-quest/forest-batch-b-preview/`。裝置測試須使用 HTTPS 或裝置本身的 localhost，確保 Web Crypto 驗證可用。本分支未部署。實機驗收須以本候選入口為準，在一般 Safari 與既有主畫面模式下冷啟動、重訪，再檢查四向移動、過橋與遮擋。診斷 E 的 PASS 適用於當時的診斷建置。

## 驗證結果

- `npm ci`、正式建置、51 項 Node 與 7 項 Python 測試通過。新增測試涵蓋選用資產成功、解碼錯誤、永未結束的請求，以及部分紋理註冊回退。
- 正式建置在 GitHub Pages 子路徑驗證。Chromium 模擬 iPhone 與 iPad 各完成一次冷啟動和三次同工作階段重訪。頁面記錄的本機首繪為 2.20／2.29 秒（冷），1.51–1.62／1.25–1.83 秒（重訪）。皆顯示 Batch B 已啟用。強制 Canvas 與 WebGL 都成功。
- 注入選用 404、停滯、解碼拒絕、WebGL 紋理提交丟錯時，皆繪製原竹林。必要北向 Run 的 404 保持鎖定並列出資產，移除故障後重試成功，本機儲存標記仍在。必要請求停滯在 20 秒提供重試，並列出未回應資產。
- 候選版 Chromium 驗證四向 Run／Idle、北向收步足點、竹冠顯隱與前後深度、溪岸碰撞、木橋、寶箱、神龕、捷徑、兩種行動橫向觸控及減少動態。正式建置驗證原工作台往返、正常霧竹林載入及第一章進村。
