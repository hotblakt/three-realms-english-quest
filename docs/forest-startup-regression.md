# 霧竹林啟動回歸｜PR #32

以 PR #31 的 `d59072175a3856223805cc21fb2c48a8f99468b5` 與 PR #32 的 `a09095a12e784f9c57f25029e8478b1da3598353` 比對。四向動畫資產及就緒門檻相同。PR #32 把選用的 Batch B 竹林圖集加入 Phaser 場景的必要預載佇列。

## 重現與判定

在 Chromium 模擬 iPhone 橫向，以初始化腳本攔截 228,190 bytes 的 Batch B WebP Blob，讓該圖的 Image 載入既不成功也不失敗。PR #31 在相同注入下正常進場，因為它不請求這張圖。PR #32 停在「正在準備四向動作」，七秒後仍無重試鍵。修復版攔截同一圖的 URL，逾時後使用既有竹林並進場。

Phaser 要等所有載入及解碼項目結束，才會進到場景 `create()`。原版四向動畫檢查與錯誤 UI 只在那之後執行。這個依賴已確認可造成無限等待。對照測試中，Batch B 回傳 404 或舊 HTML 時，PR #32 反而能正常進場，因為瀏覽器有送出失敗事件。專案未註冊 Service Worker。現有證據無法確認實機 Safari 是卡在解碼回呼、網路等待，或其他瀏覽器階段。1.125 MiB 圖集的記憶體壓力未在實機量測。

## 修復與診斷

使用獨立的 HTML Image 請求與必要動畫並行，Batch B 的等待最多三秒。檢查圖片尺寸，再以內建幀資料註冊紋理。圖集可用時保留 Batch B 生態，失敗或逾時則回退到既有竹林。圖集 URL 帶內容雜湊。場景繼續要求同一解析度的四向 Run／Idle 全部到齊，連同場景初始化成功後才啟用控制，Cast 維持背景載入。

頁面有獨立的 20 秒看門狗，涵蓋入口模組未執行或載入事件遺失。必要動作失敗列出缺少項目，逾時標記發生階段。重新載入按鈕會使用新的頁面查詢參數，不會變更本機儲存。控制始終維持關閉，直到成功完成初始化。

## 驗證

- 正式建置以 `/three-realms-english-quest/forest-preview/` 測試。Chromium 本機一輪冷啟動／同瀏覽工作階段重訪，iPhone 約 2.23／2.30 秒，iPad 約 1.67／1.60 秒。數字包含測試工具等待，不能當成實機 Safari 效能。
- 模擬慢網 220 ms RTT、390,000 bytes/s 下約 13.5 秒進場，因竹林圖集逾時使用備援。選用圖集的 404、回傳錯尺寸 WebP 均順利降級。必要北向 Run 的 404 保持鎖定並顯示重試，恢復請求後重試成功且本機儲存測試標記仍在。必要請求不返回、入口模組雜湊 404 均於約 20 秒提示重試。
- Chromium 四方向 Run／Idle、反覆換向、北向轉場足點、竹冠淡化與排序、溪岸碰撞、過橋、寶箱、神龕、捷徑，以及模擬 iPhone／iPad 橫向觸控與減少動態皆通過。正式執行環境沒有新增套件。
- `npm ci`、`npm run build`、47 項 Node 與 7 項 Python 測試通過。Playwright WebKit 的下載端點回傳 403，未執行 WebKit 或實機 Safari。仍待實機驗收冷啟動、重訪、主畫面 PWA，以及可疑停滯時的主控台階段與網路記錄。
