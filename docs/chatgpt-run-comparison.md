## 匯入方式與後續擴充

- 本次可用 `python scripts/import-alpha-run.py /path/to/source.zip scripts/eiku-chatgpt-run-recipe.json` 重現。離線工具使用 Pillow、NumPy、SciPy；執行遊戲只需既有 npm 依賴。分頁 FrameSprite 仍走既有 `import-framesprite-run.py`。
- 通用自動流程可做 ZIP 與 PNG 檢查、依格位資料或分離的 alpha 剪影切格、驗證溢出、套用統一變換、產出 WebP／來源雜湊／動作清單，以及自動產生聯絡表。建議下批 ChatGPT 圖提供獨立透明格或有明確 gutter 的規則圖集、共同腳底線與遮罩；角色、敵人與靈伴可走同一入口。
- 人工審查保留角色識別、左右支撐腳、明暗與武器一致性、自然起伏、足底換步和循環接縫。來源有肢體重疊、剪影不分離或缺步時，應回生成或重畫並重跑流程。下一批優先要求一個完整雙步循環，每一步明列接觸、壓低、通過、騰空姿勢，再做局部邊緣檢查。
- 私有庫在暫存副本重跑 `process_assets.py`，原目錄會以 `invalid ZIP input 'eiku-right-reference-v001-Run_36_sheet.zip'` 終止。該檔案大寫與底線不符 ZIP 命名規則；單純改名後，內部供應商資料夾、`sheet_01.png` 與 JSON 仍不符合一般版本素材規則。只在暫存副本移出該檔後，流程成功準備 24 個 master。未改私有庫。建議將供應商原 ZIP 存放在獨立原始動作區，透過專用匯入器輸出後再送入一般驗證。未來可新增明確的格式分流，對各類型分別報告驗證結果，避免某份素材中止全批。
- 實機 Safari 的記憶體、首次解碼與幀率待量測。下一輪比較可只按需載入單一解析度，完成已糾正的雙步稿後再評估是否取代基準。
