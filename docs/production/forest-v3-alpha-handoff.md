## 可玩流程與裁決

- 石燈小徑有竹芽練習與首通風印。西岔以原路往返，通過瀑布觀景點和藏寶處取得另一枚風印。兩路可以任意順序探索，再經原木橋進東岸。雙向快速重訪延期。
- 橋東的竹芽和風籽是兩路共同進入守衛的關卡。試煉可重玩，交戰中可撤退到安全位置。守衛固定原點 `(1069,413)`，扇掃與震波只向東。扇形半徑 72、角度 100°，震波 120×34，沿用 A 驗證的地面範圍。橙色為敵人危險區，守衛恢復時才可擊傷核心。
- 風之刃只讀取第一章合法完成狀態。第一枚風印可在東側會合點換風符，射程 144 → 168。一枚既有風印用於資格判定，風符領取後無法再次強化。沒有第一章風刃的玩家仍可用劍完成試玩。風力與體力 HUD、命中特效、反擊提示均採用試玩表現。
- 在神社旁邀請疾風。可以聽英文、比對瀏覽器的 en-US 辨識文字，或以輔助練習完成「Come with me.」。瀏覽器拒絕麥克風時可直接改用輔助練習。沒有發音分數，也沒有持久化錄音或辨識結果。認可模式會存為 `recognized` 或 `assisted`。疾風沿安全足跡跟隨，遇阻時等待或離開視野後從安全足點恢復；守衛戰中不進入打擊範圍。先招募或先打守衛均可獲得同一個羈絆成長。
- 守衛首通取得徽章與獎勵收據。往東使用既有單向捷徑回南口，南口可離開試玩。10–15 分鐘是體驗目標。正式敵人造型、疾風動畫、影空缺少的 Attack／Dash／North Cast、正式音樂與 HUD 留待後續。敵人圓形及其狀態標籤是臨時測試視覺。

## 存檔邊界

單一寫入者為獨立 IndexedDB `three-realms-forest-v3-alpha`，其 `alpha-v1` 紀錄包含安全據點、獎勵收據、風印、風符、徽章、疾風和招募完成模式。領獎交易在同一個 readwrite transaction 讀取、檢查收據與寫入，回覆以交易完成為準。撤退和重試可在保存失敗後使用。未知版本或損壞記錄不覆蓋。既有章節用原讀取器檢查風刃資格，試玩版無正式存檔寫入路徑。

## 驗證方法

```sh
node --test tests/*.test.mjs src/forest-v3/world/*.test.mjs src/forest-v3/domain/*.test.mjs tests/forest-v3/*.test.mjs
python -B -m unittest discover -s tests -p 'test_*.py'
node src/forest-v3/world/diagnose.mjs
node tests/forest-v3/alpha-browser.mjs
node tests/forest-v3/alpha-save-browser.mjs
```

後兩項需 Playwright 和執行中的 Vite 開發伺服器。可設 `PLAYWRIGHT_MODULE`、`CHROMIUM_PATH`、`FOREST_DEV_ORIGIN` 和 `FOREST_EVIDENCE_DIR`。瀏覽器測試會先將影空放在檢查點，再使用鍵盤、觸控和按鈕執行受測片段。麥克風拒權由合成瀏覽器事件驅動。存檔測試也會在測試上下文注入交易中斷和損壞資料。所有樣本與實機驗收分開記錄。

QA 的 20 案是完整驗收框架。自動案例若無完整實測封包仍顯示略過，避免把預期值當觀測值。測試環境無真機 iOS、兒童試玩或原生麥克風辨識證據。
