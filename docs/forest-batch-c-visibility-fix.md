# 霧竹林 Batch C｜站姿可見度與風靈驗證

基準為 PR #36 `afb60145c4cda66db8e1a82e2e34216a7993649b` 與 PR #37 `b3e5c143d92dca71693994803fc078409d171c6b`。製作人實機回報 6/8 通過，站定時角色消失且風靈效果不易辨識。修正與診斷僅在 `/forest-batch-c-preview/` 啟用，候選版未升版。

## 已確認與待驗證

- 對兩版的場景程式與圖集比對。PR #37 沿用四向 Run／Idle 的圖集、切換和就緒門檻，新增的神龕合成圖以足點深度 **117** 繪製。角色在神龕前時以自身足點排在神龕之上，站在其後卻會被整體屋頂、柱與牆蓋住。
- 以 Chromium 實際繪製的成對 PNG 核對：暫停場景，在相同圖格及鏡位只切換影空顯示，再計算任一 RGB 通道差大於 7 的像素。足點 **(920,101)** 南向待機在 PR #37 一般入口 Canvas 可見 3,624 像素，PR #37 Batch C Canvas 僅 75 像素（WebGL 為 68）。影空的圖格、可見旗標及 alpha 仍有效。足點 **(920,75)** 西向可見度也下降。這是已重現的場景遮擋，現象與停留方位有關，站姿本身未造成排序變化。
- 兩種解析度的四向共 118 格均有可見像素資料。檢查了入場、開放石徑、竹冠、橋兩側及橋面、神龕前後、石燈與寶箱。以角色顯示差分辨識竹葉等局部遮擋。一般入口在四個方向停住後的 1、5、15、30 秒截圖均有角色像素，PR #37 Batch C 在入口北向這四個檢查點也有角色像素。在可重現點，差分、圖格鍵與深度支持神龕遮擋，未觀察到紋理遺失或角色旗標被關閉。足點及共用接地陰影流程無需更動。
- **Safari 原回報仍待複驗。** 目前沒有製作人裝置發生消失時的足點、方向或渲染紀錄，無法排除其他位置的 Safari 圖集、GPU 或畫面合成問題。

## 候選修正與診斷

維持神龕在原深度，僅在角色足點落在其後方範圍時讓合成圖隨水平距離淡化，中心最低 alpha **0.28**。從正面或繞出範圍時恢復完整。處理使用當前足點，減少動態時照常生效，無新增 Tween。神龕圖稿、石燈、橋、角色比例、動畫速度、碰撞及互動皆維持原設定。[同足點與鏡位前後對照](../art/preview/forest-batch-c-visibility/shrine-occlusion.webp)

在 Batch C 展開「風靈地標候選版・啟動紀錄」，按「記錄角色顯示」。每秒記錄角色的圖集／幀、足點、深度、透明度、顯示與繪製旗標、鏡頭交集、Canvas／WebGL 狀態及可能重疊的前景圖層。最近 40 筆可在手機直接選取複製。前景候選為矩形範圍交集，包含透明的圖格邊界。此紀錄反映繪製條件，實際像素證據仍以截圖為準。資料只存在當前頁面。

## 風靈位置與可見條件

四個效果皆以單獨隱藏並做 PNG 差分確認有輸出。請沿鳥居後方石徑走到神龕，從階梯南方看左右路肩及正中央。需 Batch C 已成功載入，且「構圖設定 → 環境光」啟用（預設）。鏡頭需涵蓋神龕，部分光紋會被地標和角色擋住。亮度、色調及深度都沿用 PR #37。[風靈效果位置圖](../art/preview/forest-batch-c-visibility/wind-spirit-locations.webp)

| 圖例 | 世界座標 | 深度 | 靜態 alpha | 動態行為 |
| --- | --- | ---: | ---: | --- |
| 1 風弧 | (881,142)，階梯左側 | −1.08 | 0.28 | 向 0.12 淡化再復原，每段 2.75 秒 |
| 2 風靈圓環 | (920,136)，階梯正下方 | −1.10 | 0.31 | 向 0.12 淡化再復原，每段 2.75 秒 |

減少動態時維持表列原點與靜態透明度。四件都已繪製，所以沒有提高亮度。

## 可重跑的測試

`npm ci`、`npm run build`、`node --test tests/*.test.mjs` 與 Python unittest。瀏覽器差分檢查需在開發伺服器旁另備 Playwright 和 Chromium，無需變更遊戲依賴：

```sh
node scripts/check-forest-idle-rendering.mjs http://localhost:5173 canvas
node scripts/check-forest-idle-rendering.mjs http://localhost:5173 webgl
```

可透過 `PLAYWRIGHT_MODULE` 指定外部套件入口、`CHROMIUM_PATH` 指定瀏覽器。指令在測試分頁單獨注入場景觀察點，擷取正面橋口、入口、神龕前後等六組角色顯示／隱藏畫面。通過條件為角色像素差分超過 500。Chrome 的結果不能視為 Safari 實機驗收。

## 驗證結果

- 正式建置、54 項 Node 與 10 項 Python 測試通過。新增測試涵蓋神龕前後和側緣的透明度、四向兩種尺寸的 118 個 Idle 圖格。
- Chromium 的六組畫面回歸在 Canvas 和 WebGL 都通過。同足點南向待機在修正後分別量得 3,584 與 3,583 像素。修正後 Canvas 在該足點停留 1、5、15、30 秒，分別量得 3,585、3,576、3,534、3,534 像素。
- 對照效果圖逐件關閉時，風弧、圓環、蝴蝶、旋風分別改變 842、5,756、756、2,913 像素（同一 Canvas 靜止鏡位，任一 RGB 通道差大於 7）。這些數字僅用來證明該鏡位有輸出。
- 正式 GitHub Pages 子路徑建置驗證模擬 iPhone／iPad 橫向觸控、北向跑停、兩次進場及手機診斷。確認既有正式、Batch B 與診斷入口未請求 Batch C 或角色紀錄模組。工作台往返及第一章進村亦通過。
